1 · Audit of the kit today

Controls that exist
  • mc-button variants, icon, small
  • mc-input single-line only
  • mc.slider + mc-range
  • mc.toggle + mc-switch
  • mc.tabs, mc.scrub
  • variants {controls} slot
Gaps
  • No select, segmented, stepper, textarea, checkbox, radio, swatch
  • No labelled field wrapper or groups
  • Slider fixed at 110px, value inline, no rail layout
  • Switch and range have no focus ring
  • No place for controls: only the demo bar
What hurts
  • Every page hand-wires onInput to a re-render
  • State lives in closures, so the agent cannot see what the person set
  • Control values are lost on variants tab switch
  • Pure-CSS pages still need JS to bind a slider

2 · mc.state + mc.controls (optional, built)

3 · How a page uses it

// Optional. Nothing else in the kit depends on it.
const s = mc.state({ title: 'Pro', radius: 12, pad: 16, lift: 4, tone: '#4f5bd5', billing: 'monthly' })

mc.controls('#panel', [
  { key: 'title',   type: 'text' },
  { key: 'radius',  type: 'slider',    min: 0, max: 28, unit: 'px' },
  { key: 'billing', type: 'segmented', options: ['monthly', 'yearly'] },
  { key: 'tone',    type: 'swatch',    options: ['#4f5bd5', '#2fb67c', '#e2683c'] },
  { type: 'button',  label: 'Reset', onClick: s.reset },
], { state: s, layout: 'rail' })           // 'rail' | 'bar' | 'dock'

s.on(render)                               // or: no JS at all, read var(--s-radius) in CSS
